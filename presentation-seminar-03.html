Progress Review

What We Have Done Since Seminar 2

  • Unified Data Foundation: Built a 100% consistent dataset with 60 speakers and 60 non-overlapping sessions across 3 days in both data.json and data.xml.
  • Single-Page Navigation Architecture: Implemented responsive client-side views for all key areas: Home, Programme, Performers, Stages, and Practical Info.
  • Interactive Prototyping: Developed a high-fidelity vibe-coded prototype that runs with zero build setup directly in any modern browser.
  • Accessibility & Touch Target Compliance: Ensured minimum 44x44px touch targets on mobile, high-contrast palette (>4.5:1), and semantic HTML hierarchy.
Technical Architecture

Key Decisions Made

  • Pure Client-Side Architecture: Zero build tools, zero Node.js, and zero CDN dependencies. Standalone HTML/CSS/JS capable of running straight from local disk.
  • Mobile-First UI Strategy: Default single-column layout with sticky header, touch-friendly filter pills, and bottom/drawer navigation for mobile attendees.
  • State Management via LocalStorage: Custom "My Schedule" bookmarks persist reliably without requiring user authentication, database servers, or cloud backends.
  • Contextual Modal Navigation: Introduced dedicated speaker detail modals to preserve user scroll position in the timetable while diving deep into abstracts.
Interactivity

Core Interactive Functions

1. Multi-Criteria Filter

Dynamic filtering by festival Day (1, 2, 3), Stage (Vision Hall vs Tech Lab), and Technical Track.

2. Real-Time Instant Search

Instant client-side query matching against session titles, speaker names, and technical keywords (e.g., LLM, Rust).

3. Personal Agenda ("My Schedule")

Interactive session bookmarking with persistent counter badge and offline localStorage storage.

4. Performer Bio Inspector

Contextual profile modal revealing speaker credentials, abstracts, and direct schedule booking.

AI Transparency

How We Used AI & Verified Outputs

  • AI Utilization: Used Claude 3.5 Sonnet and GPT-4o for drafting responsive layout structures, generating realistic keynote abstracts, and structuring the 60-speaker JSON dataset.
  • What We Accepted: Typographic contrast hierarchy, dark aesthetic system, and the functional localStorage logic.
  • What We Rejected / Modified:
    • Rejected AI suggestions requiring Tailwind CDN, Bootstrap, and React packages to maintain strict compliance with course zero-runtime rules.
    • Normalized duplicate timestamps and templated speaker bios identified during human review into distinct 45-minute non-conflicting slots.
  • Verification Method: Automated python foreign-key validation, WCAG AA contrast audits, and DevTools viewport testing down to 375px.
